# Engineering Rules

- Prioritize correctness and maintainability.
- Make the smallest change that solves the problem.
- Reuse existing code before creating new abstractions.
- Never rewrite working modules unnecessarily.
- Avoid duplicated logic, speculative features, and overengineering.
- Prefer changes under 100 LOC when practical.
- Explain larger changes before implementing them.
- Preserve backward compatibility.
- Run relevant tests after changes.
- Never claim tests passed unless they actually ran.
- Summarize changed files and potential risks.
